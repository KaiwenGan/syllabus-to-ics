# 踩坑记录

每个坑都来自真实交付，按「症状 → 根因 → 复现 → 修法 → 验证」记录。
改 `scripts/` 之前先读一遍，这五条里有三条会让课表**静默丢课**。

---

## 1. UID 撞车：事件在导入时被静默合并（最致命）

**症状**：文件里有 187 个 VEVENT，用文本编辑器数得清；导进苹果日历只剩 152 条。用户看到"今天明明两节课，怎么只有一节"。

**根因**：UID 用「课程名 + 教室 + 周次」拼。同一周里周一 09:50 的高数和周三 08:00 的高数，三个维度全同 → 同一个 UID。iCalendar 规定 UID 标识"同一个事件"，Apple/Google 导入时按 UID 去重，后写入的覆盖先写入的。

实测：187 条事件只有 152 个唯一 UID，31 组重复，**丢 35 节**。

**复现**：

```python
uid = md5(f"{course}|{room}|{week}")          # ❌ 缺日期
```

**修法**：UID 必须含**日期 + 开始时刻**，等于把"第几次课"也编码进去。

```python
uid = md5(f"{course}|{room}|{week}|{date}|{time}")   # ✅
```

`icsgen.IcsBuilder._uid()` 会自动记录重复并在生成时报出来（`duplicate_uid`）。

**验证**：`audit.py` 打印 `UID 唯一数 / 事件数`，两者必须相等。注意——**用 dict 按 (日期, 时刻) 收集事件是查不出这个问题的**，dict 会把重复键覆盖掉，看起来"184 = 184"，其实文件里有 187 条、导入后只剩 152 条。必须单独数 UID。

## 2. 时间整体偏移 8 小时："今天没课"

**症状**：早上 8 点的课显示在 16:00，或者干脆跑到前一天。

**根因**：用了 `DTSTART;TZID=Asia/Shanghai:20260928T080000` 配一个手写的 `VTIMEZONE`。部分客户端（旧版 Outlook、某些安卓日历、部分网页端导入器）解析自定义 VTIMEZONE 失败时，会退化成"按 UTC 理解"，于是本地时间被当成 UTC，中国用户看到的时间整体 +8 小时。

**修法**：一律写 UTC 绝对时间，把时区信息算进数字里。

```
DTSTART:20260928T000000Z      ← 北京时间 08:00
DTEND:20260928T013500Z        ← 北京时间 09:35
```

**验证**：`audit.py` 检查全文不含 `TZID=`。同时保留 `X-WR-TIMEZONE:Asia/Shanghai` 只作显示提示，不参与时间计算。

## 3. `\r\r\n`：每行多一个回车

**症状**：导入报"格式错误"，或某些解析器把每行当成空行+内容。

**根因**：Python 文本模式写文件时又指定了换行转换：

```python
with open(path, "w", newline="\r\n") as f:   # ❌ newline 参数会把 \n 再转一次
    f.write(line + "\r\n")                   # 结果落盘是 \r\r\n
```

**修法**：要么二进制写（推荐，`IcsBuilder.save` 就这么做），要么 `newline=""` 后自己写 `\r\n`。

```python
with open(path, "wb") as f:
    f.write(rendered.encode("utf-8"))
```

**验证**：`b"\r\r" not in raw and raw.count(b"\r\n") == raw.count(b"\n")`。

## 4. 折行切坏中文 / 超 75 octet 被拒

**症状**：备注里的中文变成乱码，或导入器直接丢弃该字段。

**根因**：RFC 5545 要求每行不超过 **75 个八位字节**（不是字符），续行以单个空格开头。按字符数折行，一个汉字占 3 字节，75 个字符就是 225 字节；按 `len(str)` 判断永远不超限。

**修法**：按字节累计，且**不能把一个汉字劈成两半**——逐个字符累加其 UTF-8 字节长度，超限就换行并在新行前加空格。

```python
for ch in line:
    n = len(ch.encode("utf-8"))
    if cur_bytes + n > 73:
        out.append(cur); cur, cur_bytes = " " + ch, 1 + n
```

**验证**：`all(len(l) <= 75 for l in raw.split(b"\r\n"))`。

## 5. 同一节次格子里两门课，被吞掉一门

**症状**：课表 PDF 明明有 25 个上课时段，解析出来只有 24 个，少的正是"周五 3-4 节：单周高数 / 双周工程制图"里的后者。

**根因**：PDF 抽文本后是这样的：

```
3-4
高等数学AI
周数: 5周,9-15周(单)/.../地点: 教2楼205/...
工程制图F
周数: 6-14周(双)/.../地点: 教3楼302/...
6-7
```

"工程制图F" 紧跟在上一门课的详情行后面。为了修复 PDF 折行写的"续行拼接"规则（上一行含 `/` 就把本行接上去）把它当成折行，直接并进了上一条的详情字符串里。

**修法**：折行只认**明确的断行特征**，不做宽泛猜测：

- 本行以 `:` 开头（上一行断在 `学分` 后面，如 `学分\n:4.0`）
- 上一行以字段名结尾且没有值（`(周数|地点|教师|学分|…)\s*[:：]?\s*$`）
- 上一行是「其他课程」列表且没以 `;` 收尾

其余情况一律视为新条目。

**验证**：解析后打印每个星期几的条目数，与课表逐格手数对照；`build.py` 的"展开应有节数"和课表统计应一致。

## 6. 对账脚本自身的盲点

**症状**：`audit.py` 报"184 = 184，全部对得上"，但导入后确实少课。

**根因**：审计把事件装进 `dict[(日期, 时刻)] = 事件`，重复键会被覆盖（第 1 条坑正是重复 UID，两节课同占一个格子时也会覆盖）。于是"文件里有 187 条、只有 152 个唯一 UID"这件事，在 dict 层面看不见。

**修法**：审计要**多路交叉**——

1. 数 `BEGIN:VEVENT` 条数（不是 dict 长度）
2. 单独统计 UID 唯一性
3. 用集合比 `(日期, 时刻)` 差集
4. 逐条比 `SUMMARY` / `LOCATION` / `DTEND`

四条都过才算通过。

## 7. 假期 / 调休

- 校历写"10 月 1—7 日放假"，但课表本身可能这几天就没排课（比如单双周规则刚好跳过），此时剔除与不剔除结果一样——**仍然要配 `holidays`**，否则换个学期就会多出 7 天假课。
- "10 月 10 日上 10 月 7 日（周三）的课"这类调休补课，**不要自动推断**。若课表已经把补课排进了周六格子（多数学校如此），正常排即可；若没排，让用户确认后手工加一条 `courses`。

## 8. 全天事件的 `DTEND` 是排他的

**症状**：军训 9/14—9/27，日历里显示到 9/28。

**根因**：`DTSTART;VALUE=DATE:20260914` + `DTEND;VALUE=DATE:20260927` 表示"到 9/27 零点结束"，即只覆盖 9/14—9/26。

**修法**：`DTEND` 取最后一天的**次日**。`icsgen.add_allday()` 的 `end_inclusive` 参数已做 +1 天。

---

## 9. 别给全天事件加 `-PT15M` 提醒

全天事件的 DTSTART 是当天 00:00，减 15 分钟会在**前一天 23:45** 响。要提醒就写 `TRIGGER;VALUE=DATE-TIME` 绝对时刻，或者干脆不加（`allday` 默认不加）。
